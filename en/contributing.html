Contributing

A small change with a clear note helps more than a large patch with no context.

Before you open an issue

  • Check that the failure is still in the latest release.
  • Include the browser, the mode, the version, and the error code.
  • Do not paste cookies, session files, or the names of other people.

Use the issue templates. The link is Issues.

Code changes

  1. Fork and branch from main.
  2. A new browser is a Chromium or Firefox executable path. Do not add a third engine unless Teams cannot be opened with the two that exist.
  3. A new store implements Almacen and is passed to run(store=...). Do not call sqlite3 from the reading modules.
  4. A new sentence goes in both locales/en.json and locales/es.json. The error code stays in English.
  5. Do not commit datos/. That folder is the session, the database, and the downloads.
  6. Do not add a way to submit assignments, post messages, or invent selectors that were not seen in Teams.
  7. Open a pull request against main and say what changes for the person running the command.
  8. Edit the guide in the Teams-Scraper-Wiki repository. It is published at teams-scrapper-wiki.dev.

Style

Keep the names clear. Do not add a comment that repeats the line. A comment belongs only where Teams itself is misleading. No new dependency unless Selenium cannot do the job.
